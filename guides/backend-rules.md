# 后端开发规则

后端通用底线，不分语言（Go、.NET、PHP、Python 都适用）。由两份来源合并去重：技术侧规则表（2026-10-17）+ 个人经验总结。

**优先级**：项目的 AGENTS.md 等项目级指令文件与本文件冲突时，以项目为准。在既有代码（尤其是跟随上游的 fork）上，**不为了合规去重构**；发现既有代码违反本文件，报告，不动手。本文件约束的是**新写的代码和设计**。

**适用边界**：流式代理 / 网关类请求（如 LLM relay 的 SSE 长连接）天然是「请求线程内外呼、耗时数十秒」，不套用 §6「超过一秒改任务 + 轮询」和 §8「外呼走异步」。

每条三列：**规则**（要达到的结果）/ **为什么**（不守会出什么事）/ **怎么查**（能写成测试、能 grep、能在库里查出来）。提交前按「怎么查」自检，查不出来的不算做完。

## 0. 动手前先问自己

1. **数据量多大？** 现在多少行，一年后多少行，一次请求碰多少行。决定分页、索引、要不要预聚合。
2. **失败了怎么办？** 每个写动作单独问：资源怎么处理，单据落什么状态，谁从哪里补救。
3. **同一笔再来一次怎么办？** 重试、重放、重跑，都只能生效一次。
4. **两个人同时来怎么办？** 并发改同一条，只能有一个成功。定时任务和人工操作撞上呢？
5. **很久以后才有结果怎么办？** 中间态怎么存，最后归到哪一期。
6. **时区呢？** 换个机房、换种货币，「今天」还是同一天吗。
7. **历史数据动不动？** 已被引用的主键、编码、流水，一律不动。
8. **会不会无限长？** 缓存、日志、队列、表，增长多快，留多久。
9. **改了会影响谁？** 调用方、下游、别的实例、队列里排着的老任务。
10. **多快算快？** 先给接口一个响应预算，再决定怎么做。
11. **做完怎么证明？** 每条的「怎么查」就是验收。

## 1. 钱与数据

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 金额不用浮点：用整数最小单位或定点小数，带货币代码；小数位按货币查表，不写死 2 位；展示只走一个格式化函数，不在各处散写 `x/100` | 浮点有误差；小数位写死，0 位或 3 位小数的货币差几十上百倍；出现第二种货币时「数字和符号一起错」看上去毫无异常 | grep 金额字段声明为 float / double = 0；0 位和 2 位小数的货币各算一例 |
| 分账取整用四舍五入（远离零），不用截断；最后一方的份额 = 总额 − 已分 | 截断方向恒定，总是亏同一方；各自取整相加不等于总额 | 分账结果之和 = 总额，用不能整除的金额各算一例 |
| 金额加减只用数据库原子语句 `x = x ± n`，扣减带 `x >= n`；禁止读出来加完再写回 | 读改写在并发下丢更新 | 并发 N 次加减后，终值 = 逐个执行之和 |
| 入参金额恒为正，加减由操作表达；零、负数、空键一律拒绝，拒绝时什么都不写 | 负数入参能凭空造钱；成本算成负数变成反向补贴 | 每个动钱入口分别传 -1、0、空键 → 拒绝，余额和流水读回不变 |
| 流水、核算结果、审计只追加不改；更正 = 一条反向 + 一条新记录；周期汇总生成后定死 | 改历史行以后对不上账；重算容易把已发的再加一次 | 流水表、审计表上的 UPDATE / DELETE = 0；更正后原行不变、新增 2 行、合计对上 |
| 费率、价格、配置改值只对之后生效，取发生时刻生效的那条；取不到就拒绝或转人工，不当 0 | 改历史口径让已出结果变动；缺配置当 0 等于一方白付 | 改值 = 插新行带生效时间；删掉配置后重算 → 报错，不是 0 |
| 统计只认终态流水；失败走反向冲正，不改历史 | 中间态进统计，终态一变就对不上 | 造一笔申请和完成跨天的记录，统计只落在终态那天 |
| 删主行时同一事务里显式删子行和中间表，不指望外键级联 | 外键关着时只删一行，留下孤儿 | 删除前后跑孤儿检查，新增断链 = 0 |
| 同一个值、同一条公式只在一处定义：冗余副本由唯一写入函数维护，指标口径只有一个函数 | 多个写入点各走各的默认值，跨行不一致 | 冗余列写入点 = 1 个函数；公式函数有 0、边界、跨级三个算例 |
| 一律参数化查询，禁止字符串拼 SQL；动态 IN 用数组参数（PG `= ANY($1)`）；upsert 写明冲突列 | 注入；冲突列不写，冲突判定按意料之外的约束走 | grep SQL 字符串拼接 = 0 |
| JSON 列的序列化读写两个方向都确认：驱动有没有自动编解码，去查不要猜 | 读漏解码 → 类型判断失败 → 整包配置被静默换成空值；或重复编码，写得进读得出只是内容错 | 写入一个对象再读回，结构与类型逐字段相等 |

## 2. 时间与时区

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 落库一律 UTC，传输带时区偏移；禁止硬编码偏移，全仓只走一个时间工具 | 写死偏移换机房就错；本地时间和 UTC 混存，同一筛选两个结果 | grep `DateTime.Now`、`Now().Local()`、`FromHours(8)` 这类调用 = 0 |
| 带时区的入参在边界转 UTC 一次，比较只在 UTC 里做 | 存带时区的值再按 UTC 比，到点的状态不变 | 入参带 +8 的时间，库里读回是 UTC 值 |
| 按天筛选、统计、定时任务的「今天」按归属方时区切，不用服务器 Now / Today；切日表达式全仓只写一处 | 按服务器时区切日，别的时区的归属方落错日 | +8、本地 00:30 建的行：筛当天出现、筛前一天不出现；切日表达式 = 1 处 |
| 时间区间一律左闭右开 `[start, end)` | 闭区间让边界时刻的记录两期都算或都不算 | grep 时间列上的 `<= @end`、`BETWEEN` = 0；恰在 end 的记录只进下一期 |
| 每张按天汇总的表写明切日用哪个时间（发生 / 完成）；跨期完成的记录必须且只能落进一期 | 按发生日汇总，延迟完成的永远进不了任何一期 | 造一笔跨期记录，所有期汇总之和 = 这一笔 |
| 按 UTC 日期分区的存储，查本地日先扩 ±1 天再在应用层精确过滤 | 直接按 UTC 日取，多一天或少一天 | 本地日查询结果与明细逐条对账，差 = 0 |

## 3. 幂等与并发

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 新建和动钱的写带幂等键，空键拒绝；同键同参返回首次结果，同键异参拒绝；键按（归属方, 来源, 业务单号）收窄 | 无幂等键，重试重放生效两次；不按归属收窄，别人的键能短路你的请求 | 同键两次 → 同结果、副作用 1 次；换归属方同键 → 不命中；空键 → 拒绝 |
| 幂等键用交易号不用单据号；一张单据多次到账逐笔入账，末笔标结束 | 按单据号判重，第二、三笔被当重复丢掉 | 同单据不同交易号各入账一次，合计正确 |
| 幂等和唯一性最终靠持久层唯一约束兜底；缓存只加速；insert 前先 exists 不算去重 | 缓存过期认不出重复；exists 再 insert 并发有缝（TOCTOU） | 同一消息投两次 → 落库 1 行；每个不可重复的业务键有唯一索引 |
| 状态变更用条件更新（WHERE 旧状态）并判受影响行数，0 行即失败；禁止先 SELECT 再 UPDATE，禁止固定返回成功 | 两步之间别人已经改了，自己还以为成功 | 10 个并发改同一条 → 成功 1 次；受影响行数未使用的调用 = 0 |
| 先查后写放同一事务，事务内不混用全局连接；累计字段用 `x = x + ?` 的 upsert，不用覆盖式 | 查在事务外等于没查；覆盖式 upsert 把累计值清掉 | 事务块内出现全局连接对象 = 0；并发 upsert 后累计值 = 各次之和 |
| 有副作用的长任务加互斥并限并发 | 同一任务触发两次，互相覆盖或卡死后续 | 同任务并发触发 → 第二个被拒或排队 |

## 4. 状态机

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 状态只走列出的跃迁（从、到、谁、前置条件），表外拒绝；终态不可逆 | 没有跃迁表，作废后还能重做 | 状态数 × 操作数全集用例：表内成功并读回，表外拒绝且状态不变 |
| 没有前态的事件直接拒绝并告警，不默认放行 | 找不到单据还照样入账，钱凭空多了 | 对不存在或已终态的单据发事件 → 拒绝 + 告警，库不变 |
| 同一单据的事件按单据 id 分区保序，消费端先判状态再写 | 结果和回滚乱序，后到的覆盖先到的 | 同单据乱序投两条 → 终态按业务顺序 |
| 作废、驳回、超时、失败按原数释放占用；撤销和重算用反向流水对冲；扣减设下界 | 不释放资源被占死；重算累加一次多一次；无符号计数减过头溢出 | 占用 → 作废后可用量 = 占用前；重算两次合计不变；减到 0 以下被拒 |
| 影响可用余额的状态变化同步完成，异步只做统计 | 审核异步，期间再开一单取到旧余额 | 连续两次提交，第二次读到第一次之后的余额 |
| 调外部系统的写操作写清失败、超时、结果未知三种情况：资源怎么处理、单据落哪个态、谁从哪补救；有延迟结果的单据有最晚时限 | 超时重试没兜底，单据卡中间态没人管 | 每个外呼写操作三个分支各有用例，有补救入口 |

## 5. 权限与归属

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 每个读、写、存在性判断、批量 id 都按调用方归属过滤，在基类里强制加，不信任入参；别人的和不存在的返回同一响应 | 换个 id 就能看、能改别人的数据 | B 的令牌 × A 的每个 id × 每个操作 → 同一响应，A 的数据不变 |
| 归属上下文为空直接拒绝，不许默认 0；测试带和真实请求一样的请求头 | 上下文为 0 还往下跑，取到空值继续写 | 不带上下文的请求 → 拒绝 |
| 主键和业务 id 命名区分，不互相代用 | 两者不相等时更新错记录 | grep 混用调用 = 0 |
| 可变的归属关系在事件时刻快照 | 归属一变，历史统计口径跟着变 | 改归属后历史记录的归属字段不变 |
| 每个操作一个权限码，唯一真源是路由注册表，启动自检对不上就退出；不能授出比自己大的权限；撤权、停用、封禁对下一个请求立即生效 | 无码路由裸奔；能自赋超管；封禁了在线会话照常用 | 低权账号给自己加高角色 → 拒；封禁后旧令牌 → 401 / 403；码表对不上 → 非零退出 |
| 比对秘密的入口连续失败 N 次锁 M 分钟，常量时间比较，秘密为空时验签恒拒；外部回调带时间戳和 nonce 防重放 | 验证码可无限试；空 secret 也能验签通过；回调可重放 | 第 N+1 次失败被拒；secret 配空 → 任何签名被拒；重放 → 拒绝 |

## 6. 接口与错误

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 失败不伪装成功：查询出错不返空列表，统计不返恒 0 或 -1，无效参数拒绝而不是静默丢弃 | 错误被当成「没数据」，账越对越不上 | 注入下游错误 → 响应是错误码，不是 200 + 空数据 |
| 错误用稳定的码不用文案，前端按码翻译；新增码同时补齐全部语言包 | 文案没法多语言；缺语言包就回退 | 错误码集合 vs 每个语言包比对脚本，缺项退出码 1 |
| 异常不吞：先落日志再返回或重抛；长流程每步记录并带 TraceId；对外不泄露堆栈 | 吞掉线上无法排查；回堆栈泄露内部 | grep `catch {}`、`except: pass`、`_ = err` = 0；生产错误体不含 stack 和路径 |
| 入参边界明确：数值有上下界，必填 = 去空格后非空（空串、0 值 id 算缺），绑定失败返回 400，不用零值继续走 | 空键、空秘密入库；零值继续是静默错误 | 每个边界值一条拒绝用例且写集不变 |
| 更新只改提交的字段；读时脱敏的值原样提交回来等于不改 | 读脱敏 + 写全量覆盖，编辑一次把明文销毁 | 读到掩码 → 原样提交 → 库内原值不变 |
| 对外接口只加不改；破坏性改动分三步发布、每步可回退、按调用方逐个切换；对外报文只在一处组装；外部编码先映射到内部有限词表，表外拒绝 | 改一次取值等于让所有接入方重接 | 契约字段删改在 CI 红；传未知词 → 入口拒绝 |
| 可能超过一秒的操作改成提交任务 + 轮询（流式代理例外，见文首） | 同步等到超时，请求线程被占满 | 长操作有任务 id 可查 |
| 动钱、权限、配置的写记审计：操作人 + 改前 + 改后；只记改动不记查看（读取秘密除外） | 没有改前改后无法对账和追责 | 写后审计表 +1 且含 before / after |

## 7. 查询与分页

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 禁止无 WHERE 无 LIMIT 的查询、无 WHERE 的 UPDATE / DELETE；分页有默认值和上限，排序末位加主键；导出和全量处理走异步任务 | 无上限等于全表拉取；排序不稳定翻页重漏 | pageSize 超上限被钳；25 行分页走完无重无漏 |
| 循环体内不查库不写库；where / join / order 列有索引；只投影需要的字段，敏感列不进返回实体 | N+1；`SELECT *` 暴露密码哈希 | 循环内 db 调用 = 0；EXPLAIN 无全表扫；响应 key ⊆ DTO 白名单 |

## 8. 缓存、后台任务与留存

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 每个缓存键必有 TTL，一组键用同一个函数设过期，TTL ≥ 业务最长跨度；写路径提交后失效对应键 | 无 TTL 的键把集群挤满；写后不失效读到旧值 | grep 缓存 Set 无过期参数 = 0；写后立即读 = 新值 |
| 缓存只做加速不做真源；幂等、状态这类业务事实落持久层 | 缓存过期业务事实就丢了 | 清空缓存后业务行为不变 |
| 同一个库的多步写在同一事务 | 第二步失败第一步已落库 | 第 k 步注入失败 → 前面的写读回不存在 |
| 副作用（通知、外呼、文件处理）不在事务内同步调，走异步并有重试、失败处理、告警 | 同步外呼拖死请求；任务静默失败 | 每个任务定义重试次数、退避、失败处理 |
| 异步任务的参数签名只能在末尾追加带默认值的参数 | 队列里排着的老任务会被新代码执行，回滚时反过来也一样 | 任务签名 diff 只有末尾新增带默认值的参数 |
| 定时任务统一在一个调度入口注册，并做单实例控制 | 自起后台循环，多实例 / 蓝绿下重复执行或旧实例跑旧逻辑 | 双实例启动，任务执行次数 = 1 |
| 每个新存储（表、主题、日志、缓存）写明「增长 × 留存 = 上限」；分析类大表按时间分区；周期任务只处理有变化的 | 没有上限的存储只增不减 | 新表 / 主题设计里有留存一行；大表 DDL 有分区 |

## 9. 日志

- 用标准日志库，按模块命名 logger，日志配置只在一个地方做。
- **每个独立进程入口**（Web、worker、脚本）单独初始化日志，并放在其他重量级 import 之前；漏了的进程 INFO 日志被静默丢掉。
- 日志级别用环境变量控制，值非法时回落默认并报一条错，不让进程启动失败。
- 日志按天滚动留 N 天，单请求日志行数有上限（按请求链路的关键节点定，不拍固定数）；逐请求刷屏的第三方库日志压到 WARNING。
- **请求 / 响应正文、token、密钥、个人信息不进日志**，任何级别都不行。

## 10. 迁移、配置与上线

| 规则 | 为什么 | 怎么查 |
| --- | --- | --- |
| 被引用的主键和编码只增不改；结构变更走新表新接口 + 迁移脚本 | 改了被引用的值，所有引用处一起错 | 变更清单里没有改已有主键 / 编码的语句 |
| schema 只加不删（expand / contract）：删列、改名、改类型、加 NOT NULL、加 CHECK 拆两次发版，先加新的迁数据，下一版再删旧的；删列删表单独确认 | 部署时新旧版本同时在线，回滚也要能跑；删表重建丢数据 | 迁移 DDL 无 DROP（显式开关除外） |
| 索引、唯一约束、枚举在 schema 代码里声明，不手工 ALTER；分库时每个实例都跑到 | 手工 ALTER 漂移、漏实例 | 所有实例 schema 比对一致 |
| 已执行的迁移文件不可修改（含注释），要改写新迁移；台账表保证每个只执行一次；每个文件一个事务，必须事务外执行的（`CREATE INDEX CONCURRENTLY`）单独一个文件；多人并行用时间戳命名 `YYYYMMDDHHMMSS_说明.sql` | 改了已执行的迁移，各环境状态分叉；顺序号必然撞号 | 已执行迁移文件的 git diff = 0 |
| 不写「靠每次启动重跑来维持」的数据修正语句；需要一直成立的规则放应用逻辑或定时任务 | 启动顺序、多实例下行为不可控 | 迁移里无每次启动都跑的 UPDATE |
| 改存量数据先在老数据快照上 dry-run，输出范围和条数，按唯一键去重、带结束边界，导入后核对计数 | 脚本重复跑、跑过头，数据翻倍 | 迁移脚本附受影响行计数 SQL 和实测数 |
| 安全相关配置缺失、为空、长度不对 → 启动失败，不回落默认值，开发和正式一个规矩；密钥不进仓库不进日志；生产配置不残留测试域名和本机地址 | 回落到开发密钥等于没密钥 | 空密钥启动 → 非零退出；仓内和日志 grep 密钥样式 = 0 |
| 配置只改配置源，按环境注入，不写死外部地址；环境变量覆盖配置文件的键名规则写进测试；生产上是什么值去生产上查，不拿本地推断 | 直接改部署目录的配置下次发布被覆盖；环境变量盖不住驼峰键，静默失效 | 单测：文件设 `a.bKey=1`、环境设 `A_BKEY=2`，加载后 = 2 |
| 每次部署保留版本目录可一键切回；蓝绿任一侧失败两侧都回退；部署文件提交前跑校验（`nginx -t`、`compose config`、`bash -n`）；有副作用步骤前的检查是闸门（非零退出）不是打印 | 发布失败两边版本不一致；打印了冲突照常往下跑 | 模拟冲突 → 脚本非零退出且无写入 |
| 优雅停机三者配平：容器停止宽限期 > worker 等任务做完的时间 > 单个任务超时 | 只调大任务超时，长任务每次部署被强杀，重跑时外部调用费用重复计 | 三个配置值满足不等式 |
| 对生产执行批量命令前先看清波及哪些服务（`docker compose up --dry-run`，只动单个服务加 `--no-deps`） | `up -d <服务>` 沿 depends_on 递归重建，一条命令重建整个栈 | 执行前贴出 dry-run 输出 |

## 11. 测试与检查脚本

**写断言**
- 测某一层防御，断言落在只有这一层才会产生的结果上，否则删掉这层测试照样绿。
- 验收断言从存储读回，不信响应体；每条拒绝用例配一条放行用例（「全部拒绝」的实现也能让拒绝用例过）。
- 计数断言用独立 COUNT，不数「带 LIMIT 和排序的列表」：历史数据会把新数据挤出列表。
- 测试替身不能比真实实现宽松：`.get(key, "")` 会把「上游没给这个字段」伪装成正常。
- 用真数据库测数据库逻辑；集成验证接真实测试环境、真实请求头；mock 只用于前端契约。

**跑测试**
- 报「通过」前确认用例真跑了：看 SKIP 计数；「通过数比预期少又没失败」先查是否因环境变量没设被静默跳过。
- 新用例先把被测行为改坏看它红；重构前先故意改坏几处关键逻辑量一下测试网。
- 真库测试用独立库名、串行跑、跑完 DROP；多窗口并行各用独立库名（否则互相清表，表现为随机失败、单跑必绿，极易误诊成并发 bug）。
- 加全局用例超时，把永久挂起变成带堆栈的失败。
- 「结果打出来了进程不退出」：先查遥测 / 日志上报是否在重试一个不存在的地址。
- 有计时断言的用例不和重负载任务并发跑。

**检查脚本、CI 门禁**
- 先断言「找到的检查对象数 > 0」，再断言「没有违规」：路径或正则写错时零命中看起来就是全部通过。
- 新规则塞一个违规样例确认会报；拿现有代码跑只证明不误报，证明不了不漏报。
- 不留长期红的门禁；存量清不完就只拦新增。
- `cmd | tail; echo $?` 读到的是 `tail` 的退出码。

## 附：特定技术栈的坑

**Python + asyncpg + PostgreSQL**
- asyncpg 默认没注册 JSONB 编解码：写入要 `json.dumps`，读出是 `str` 要 `json.loads`。推荐：`v if isinstance(v, (dict, list)) else json.loads(v or "{}")`。
- 老项目不要临时全局注册 codec：已有的 `loads/dumps` 会一起报错或变成重复编码。
- 连接池绑定的 event loop 和当前 loop 不一致时（pytest-asyncio 每用例新 loop），关旧池用同步 `terminate()`；`await close()` 会偶发永久挂起。
- 全局超时用 `pytest-timeout`。

**OpenTelemetry**
- import 阶段就全局插桩的，本地跑测试要关（如 `OTEL_DISABLED=true`），否则跑完卡几分钟重试上报。

**Windows 开发机**
- Python 打印中文报 `UnicodeEncodeError`：加 `PYTHONIOENCODING=utf-8`。
- 长时间跑异步测试偶发 `WinError 10055`（socket 缓冲区耗尽）：环境问题，单独重跑能过。
